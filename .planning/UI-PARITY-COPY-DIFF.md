# UI parity — Bulgarian copy that differs between web and mobile

Generated 2026-10-01. Per screen pair, every Cyrillic string literal (the copy-lock extraction) **plus JSX text children** (added here — see the blind-spot note) in the web files vs the mobile files that implement that screen. **This is a candidate list for the founder's ruling — nothing is unified.** "Web only" = present in the web screen's files and absent from the mobile screen's files, and vice versa.

Limits (read before ruling): heuristic, not proof. A string moved between files of the same screen counts as shared; a reworded string appears once on each side. Copy that comes from a shared content module (@stellaeum/core, e.g. welcome/quips/interpretations) or from the server (Oracle/horoscope text) is single-source and not in the diff. Strings built from template parts or props are not captured. **Blind spot found while generating this:** the copy-lock (`scripts/i18n/extract-literals.mjs`) matches only quoted literals, so JSX text like `<Text>Дневник</Text>` is NOT locked — 530 web and 353 mobile JSX-text occurrences sit outside the lock today.
