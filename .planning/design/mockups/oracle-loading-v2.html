New composition, flagged (not a new primitive)

The three-glyph row. It is built only from the existing glow mechanism and glyphs.ts paths. Per the design reference a new composition is flagged, not slipped in. It replaces the current Oracle loading glyph (spinning ring + rotating diamond via useSpin/usePing).

Pacing findings

  • Re-measured 2026-10-07 (20 real Oracle generations, one at a time, thinking level low): min 2.7 s, p50 4.1 s, p90 8.9 s, p95 9.2 s, max 12.2 s. The earlier figures in this file (p50 3.3 s, p90 6.6 s) came from an earlier run on a quieter day and are superseded. Text steps are now 0 / 1.5 s / 3.0 s: the third stage (and its glyph) is on screen for 17 of the 20 measured calls (85%); the other 3 finish before 3.0 s and never need it. Each glyph still lights together with its stage.
  • The "taking longer" threshold stays at 10 s — the measurement supports it. It sits just above p95 (9.2 s) and fires for exactly 1 of the 20 measured calls (12.2 s, 5%), i.e. for a genuinely slow call, not an ordinary one (12 s would have caught the same single call). It is well below the 25 s primary-model timeout, after which the fallback model answers (GEMINI-SLOW-NO-FAILOVER). Earlier text claimed the line never fired in 20 calls; that was true of the earlier, faster run and is superseded.

Reduced motion

All three glyphs shown static and lit; no breathing, twinkle or fades; text still advances on the same timings but swaps instantly; the reading appears without a fade.
