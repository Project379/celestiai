### Decisions to surface for SR 7 investigation

1. **Streaming vs JSON** — recommend JSON (consistency with SR 5 pattern). Streaming requires `react-native-sse` or polyfill; iOS finickiness logged as REVISIT.
2. **Sentinel marker rendering** — strip-to-plain (consistency with SR 5.3) vs port `parseSentinels` with colored `<Text>` spans. Recommend strip; polish round handles colors.
3. **Oracle route shape** — full-screen route (`/oracle`) vs modal-over-tabs (`/oracle?modal=1`) vs bottom-sheet half-modal. Web's `OraclePanel` is desktop sidebar / mobile bottom-half. For native iOS feel, recommend full-screen modal route with header bar showing «Оракул» title + back button.
4. **Tier gating data source** — mobile needs `subscription_tier` from somewhere. Web reads it from `users` table at server-render time. Mobile candidates: extend `useFirstChart` to also return tier, OR new `useSubscriptionTier` hook. Recommend separate hook for separation of concerns (chart vs tier are unrelated domains).
5. **Topic locking copy** — when free user taps premium topic, what's the unlock message? Web uses Bulgarian copy in `LockedTopicTeaser.tsx`; mirror verbatim.
6. **Cross-highlight to NatalWheel** — web has the planet-sentinel-tap → wheel-highlight bridge. Mobile would need similar plumbing IF the user can scroll between Oracle and Карта easily. For SR 7 minimum: skip cross-highlight (Oracle screen is a separate route, not a panel). Founder ratifies.

## Conventions established (must preserve)

### Speed-mode discipline

- Single investigation pass before any code in a sub-round
- Surface implementation plan + sub-decisions in ONE message, founder ratifies in ONE response
- Execute all sub-commits sequentially without per-commit halts
- Combined commits where work is cohesive and small (<400 lines)
- TypeScript green between commits (mechanical check, no founder gate)
- Founder verification ONLY at sub-round close
- Sub-round close summary doubles as next-sub-round green light unless founder pauses

### Halt triggers (founder gate required)

- Real blockers: TypeScript errors, peer dep conflicts, version mismatches, schema migrations, novel architectural choices
- Conflict-surfacing protocol: math/logic discrepancies, cross-platform parity concerns, founder ratification overridden by evidence
- Scope decisions: Bulgarian copy choices for mobile-only surfaces, library selection where multiple viable options exist
- Sub-commit exceeds 400 LOC AND has multiple decoupled concerns
- 2 failed fix attempts on any single bug → diagnostic instrumentation, not 3rd hypothesis fix
- 2–3 failed fix attempts on third-party library → evaluate "build it ourselves" as first-class option (lesson from SR 4.4 picker saga: ~190 LOC custom TimePicker resolved 8-fix-attempt failure)

### Bulgarian copy discipline

- Shared surface (web has equivalent): mirror verbatim, including hyphen-vs-em-dash, exact eyebrow text, exact Bulgarian copy
- Mobile-only surface: bulgarian-skill calibration (auth screens calibrated in commit 1.4d, you-tab Премиум/Настройки calibrated in 5.5)
- Verb-object pairings matter — `пусна` works for grip/abstract demonstratives but NOT for `рани`/`мисли` (lesson from SR 5.6-fix-1)
- Calques to avoid: passive voice, gerund constructions, phrasal verb literal translation, "feels" patterns
- Reference: `.claude/skills/bulgarian-skill/references/{natural-phrasing,style-and-expression,astrology}.md`

### Architecture lifts to packages/core

When a piece of editorial logic / data needs to live on both surfaces:

- Lift web file to `packages/core/src/{domain}/{file}.ts`
- Add subpath export to `packages/core/package.json`
- Migrate web import to `@stellaeum/core/{domain}/{file}`
- Mobile imports same path

Established lifts:
- `@stellaeum/core/welcome` (5.4) — composeWelcome, meteor-showers, sun-sign
- `@stellaeum/core/charts/interpretations` (6.1) — planet interpretations
- `@stellaeum/core/charts/glyphs` (6.6) — zodiac SVG path data

### Mobile package boundaries

- `@stellaeum/astrology` workspace dep added in 6.2 — mobile imports ONLY from `/client` subpath (pure types + constants, no sweph). Bare-entry imports MUST NOT appear in mobile code (would pull Node.js-native modules through Metro).
- `@stellaeum/core` workspace dep — same caution: import only from subpaths that don't transitively pull `sweph` or `@supabase/supabase-js` server-side dependencies on mobile.
