**Authoritative spec:** `.planning/SECURITY-MODEL.md` lines 79–83 (footnote under the table classification row). That footnote already locks: USER_DATA SELECT-only RLS (per migration `20260413141504_schema_hardening.sql`); scope = AI generation surfaces (Oracle readings, daily horoscope, future synastry interpretations); monthly calendar period anchor; fresh-start with no backfill of existing reading counts; refactor of `/api/oracle/generate` step 7 from row-counting on `ai_readings` to quota-table reads; helpers to ship — `getCurrentPeriodQuota` (creates row if absent) and `incrementQuotaUsage` (atomic SQL `UPDATE … SET ai_readings_used = ai_readings_used + 1` to avoid read-then-write races); cache hits MUST NOT count against quota (preserves SR 7 behavior); premium tier uncapped initially (`NULL` `ai_readings_limit` or no row created — reconsider when cost-envelope analysis surfaces a defensible cap number); daily-horoscope cap (currently uncapped) gets 1/day enforcement via the same quota table.

**Pending founder decision before investigation pass fires:** unified quota (single `ai_readings_used` counter shared across all AI generation surfaces) vs. separate caps (Oracle + daily horoscope each have their own bucket — separate columns or separate rows per surface). The decision changes the schema shape and the helper signatures, so it gates the investigation pass rather than emerging from it.

**Halt triggers active during B.0f execution:**

- **Race conditions on quota increment.** Atomic SQL `UPDATE` (not read-then-write in application code) is the only safe pattern under concurrent generation requests from the same user. Surface for ratification if any helper signature would require read-then-write.
- **Period rollover logic.** First request of a new month must atomically create-or-find the current-period quota row. The `getCurrentPeriodQuota` helper signature should encode this; surface if the implementation drifts toward separate find + create branches.
- **Cache hits MUST NOT count against quota.** Preserve the SR 7 behavior — only fresh generations decrement. Surface if any code path increments quota before checking the cache.
- **Test user quota state immediately after deploy.** Fresh-start means existing test reading counts on `ai_readings` don't carry into quota rows; the first generation request of the new period creates a row from zero. Document but acceptable for test data — no backfill migration needed.

**Estimated scope:** 200–400 LOC. Lower bound assumes unified quota (smaller schema + simpler helpers); upper bound assumes separate caps (more columns/rows + per-surface helper variants).
